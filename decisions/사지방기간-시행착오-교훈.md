## bodetail 마스터플랜 (사업 전략) 작성 이력

CEO 관점 요청으로 마스터플랜을 두 차례 작성함.

- **1차(간단 버전)**: 시장 판단(국내 남성 그루밍 시장 1.1조·연 3% 성장 — 느림 / 글로벌 시장은 크고 빠름), bodetail의 구조적 무기(콘텐츠 한계비용 0, 롤온 폼팩터 차별화, 포지셔닝 공백), Phase 0~4 로드맵, 엑시트 시나리오(구다이글로벌형 애그리게이터 1순위).
- **2차(완전판, PDF 16페이지)**: "너무 구체적이지 않다"는 피드백으로 재작성. 팔로워 성장 사다리(0→1K→10K→5만→10만→30만) 각 구간 전술, 2026.07~2028.12 월별 실행 캘린더(30개월)+2029~2031 분기별, 런칭 D-30~D+30 일 단위 플레이북, 커머스·마케팅·재무·엑시트·리스크 매트릭스. 핵심 원칙: **"게이트 조건 통과 못 하면 다음 단계로 안 넘어간다."**
- **미완료**: PDF 실물 파일이 `brand/`에 아직 저장 안 됨 — 준영이 파일을 확보하면 `brand/masterplan-v2.pdf`로 볼트에 추가 필요.

## 대형 사고 — 파일 덮어쓰기 (재발방지 규칙의 기원)

GitHub Actions는 "성공(초록불)"인데 `posts/`에 아무것도 안 생기는 상황 발견 → `generate_daily_post.py`를 열어보니 **리버니 네일룸 생성기 코드**가 들어있었음. 사지방에서 복붙 작업 중 다른 프로젝트 코드를 실수로 덮어씀. GitHub 파일 History에서 사고 이전 마지막 정상본(커밋 `4763868`)을 Raw로 복사해 복구.

**재발 방지 규칙**: "파일 첫 5줄 확인 — bodetail 파일은 `bodetail 일일 게시물 완전 자동화`로 시작해야 함. '리버니'가 보이면 잘못된 파일." (콘텐츠 자동화 저장소 CLAUDE.md에 절대 규칙으로 등록됨)

## 핵심 교훈 5가지 (반복 패턴)

1. **"에디터 CSS만 고치면 미리보기만 예뻐지고 최종 산출물은 그대로"인 함정이 두 번 발생** (게시물 레이아웃, 릴스 자막스타일) — 항상 렌더러 코드도 같이 확인해야 함. 상세: [[content/편집기-진화-렌더러함정]]
2. **파일 덮어쓰기 사고가 반복될 위험** — "첫 5줄 확인" 규칙으로 대응(위 참조)
3. **외부 검토(제미나이)를 받아오는 패턴이 유효했음** — 5라운드는 실제 결함을 찾아 코드 개선에 기여, 6라운드째 사실관계 오류가 나온 걸 신호로 검토를 스스로 종료. 맹신하지 않고 매번 실측/웹서치로 검증 후 반영. 상세: [[marketing_auto/MA_06_AI릴스파이프라인-힉스필드]]
4. **"완전 자동"이라 부르지만 실제로는 반자동인 지점을 명확히 인지하고 소통** — 힉스필드는 채팅 세션 내에서만 동작, GitHub Actions가 대신 호출 불가
5. **비용 통제가 설계 원칙 최상단에 있음** — "콘텐츠 한계비용 0"이 브랜드 핵심 해자라는 마스터플랜의 결론이 이후 모든 기술 판단(클립 재사용, 주 1회 플래그십, 매일 자동화 여부)의 기준이 됨
