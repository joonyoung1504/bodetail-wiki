# 콘텐츠 볼트 운영 가이드

> 이 노트는 **콘텐츠 팩토리 볼트** (이 위키 볼트와 별개)에 대한 설정 가이드다.  
> 콘텐츠 볼트 = 영상 실험 데이터 저장·분석소. 위키 볼트 = 사업 두뇌(지식).

## 5개 핵심 객체 (온톨로지)

| 객체 | 역할 | 예시 |
|------|------|------|
| **Content** | 릴스 1개 = 노트 1개. 발행 변수 + 결과 기록 | R-20260616-01 |
| **Hook** | 첫 3초 유형별 성과 추적 | Hook - 충격질문, Hook - 공감고백 |
| **Format** | 영상 구성 유형별 성과 추적 | Format - 비포애프터, Format - 길거리투표 |
| **Topic** | 페인 주제별 성과 추적 | Topic - 물어뜯기, Topic - 호감포인트 |
| **Episode** | EP 단위 세계관 관리 | Episode - EP1 손톱 |

**3가지 철칙**:
1. 1 영상 = 1 노트 (절대)
2. 발행 시점에 **입력 변수를 즉시 기록**
3. 성공 기준 = save_rate ≥ 0.04 (저장률 4%)

## 폴더 구조

```
콘텐츠볼트/
├── 0_System/          ← 대시보드, 규칙, 이 가이드
├── 1_Content/
│   ├── _Inbox/        ← 발행 전 초안
│   ├── Success/       ← save_rate ≥ 0.04
│   └── Fail/          ← save_rate < 0.04
├── 2_Patterns/
│   ├── Hooks/         ← 훅 유형별 노트
│   ├── Formats/       ← 포맷 유형별 노트
│   ├── Topics/        ← 주제 유형별 노트
│   └── Episodes/      ← EP 시리즈 노트
├── 3_Products/        ← 제품별 정보 (손톱 세럼 등)
├── 4_Analytics/       ← 주간·월간 성과 요약
└── _Templates/        ← 노트 템플릿
```

## 콘텐츠 노트 frontmatter 스키마

```yaml
---
type: content
id: R-20260616-01

# 입력 변수 (내가 통제한 것) — 발행 즉시 기록
topic: "[[Topic - 물어뜯기]]"
hook: "[[Hook - 충격질문]]"
format: "[[Format - 비포애프터]]"
length_sec: 15
subtitle_pos: 하단          # 상단/중앙/하단
subtitle_style: 세리프-흰-대
bgm: 잔잔
cta: 대기자폼
publish_at: 2026-06-16T20:00
made_by: real               # real(실촬영) / ai(생성)

# 결과 지표 (Antigravity 자동 수집)
reach: 0
saves: 0
shares: 0
save_rate: 0

# 판정
verdict: ""    # save_rate≥0.04 & 도달 중앙값↑ → success
---
```

## Dataview 분석 쿼리

### 성공 훅×포맷 조합 집계
```dataview
TABLE rows.save_rate AS "저장률들", length(rows) AS "표본수"
FROM "1_Content/Success"
GROUP BY hook + " × " + format
SORT length(rows) DESC
```

### 주제별 평균 저장률
```dataview
TABLE length(rows) AS "발행수", average(rows.save_rate) AS "평균저장률"
FROM "1_Content"
GROUP BY topic
SORT average(rows.save_rate) DESC
```

**통계 기준**: 표본 ≥5 = 참고, ≥10 = 신뢰

## 자동화 루프 (전체 흐름)

```
[0] 라우터 — 복잡도 판단: 단순 → Ollama, 복잡 → Claude
[1] 기획:   Claude가 Success 패턴 읽고 콘티 JSON 생성
[2] 제작:   Higgsfield 보조컷 + 실촬영 (서사·비포애프터는 반드시 실촬영)
[3] 코드:   Claude가 발행·수집 코드 작성 → Antigravity가 실행
[4] 발행:   Antigravity → Meta API 업로드 + 입력변수 기록
[5] 측정:   Antigravity → N일 후 Insights(도달·저장·공유) 수집
[6] 저장:   GitHub push → Obsidian 노트 생성/갱신
[7] 분류:   Ollama가 save_rate 판정 → Success / Fail 폴더 이동
[8] 분석:   Dataview → 변수 조합별 성공률 집계
[9] 학습:   성공 패턴 요약 → Claude에 재투입 → [1]로 순환
```

### 도구 역할

| 도구 | 역할 | 비유 |
|------|------|------|
| 라우터 (코드) | 복잡도 보고 Ollama/Claude 분배 | 택배 분류기 (if문, 토큰 0) |
| Ollama (로컬) | 분류·태깅·요약·초안 — 80% | 성실한 인턴 (무료) |
| Claude Opus | 콘티·전략·서사·카피 — 20% | 크리에이티브 디렉터 |
| Antigravity | 코드 실행·발행·수집 | 행동대장 (손발) |
| Obsidian | 온톨로지 저장·분석·대시보드 | 기억·뇌 (데이터 금고) |
| GitHub | raw 백업·버전관리 | 안전 금고 |

### 단계별 자동화 현실

| 단계 | 자동화 | 비고 |
|------|--------|------|
| 분류·측정·저장·분석 | 완전 자동 OK | 규칙 명확 → 먼저 자동화 |
| 콘티·카피 생성 | 반자동 | Claude 생성 → 사람 검수 |
| 핵심 영상 (서사·비포애프터) | 수동 (실촬영) | 해자. AI 양산은 보조컷만 |
| 발행 (Meta API) | 확장 단계 | 처음엔 예약 발행 |

**구현 순서**: ① 수동 루프 한 바퀴 (25h 스프린트) → ② 분류·측정 스크립트 → ③ Ollama 라우터 → ④ Meta API 무인 발행  
한 번에 다 만들지 않는다. 발행이 1순위, 자동화는 검증된 단계부터.
