# 표지 headline 강제 고정 결정

## 무엇을 결정했나

`generate_daily_post.py`가 만드는 게시물의 표지 큰 제목(`headline_main`)을 Claude가 자유
생성하지 못하게 하고, `content/topics_30.json`의 `title_main` 값으로 **코드가 강제로
덮어쓰도록** 고정했다(합의된 A안). Claude에게는 부제(`headline_sub`)와 구체 약속
(`headline_serif`)만 맡긴다.

## 왜 이렇게 결정했나

미해결 이슈로 [[marketing_auto/MA_05_데일리포스트생성기]]에 남아 있던 문제: DAY1에서
예고한 "다음 편" 제목과 실제 DAY2로 생성된 게시물의 표지 문구가 어긋났다. 원인은
`title_main`이 프롬프트에 "참고 소재"로만 주어지고, 실제 표지 문구는 Claude가 매번
새로 짓게 되어 있었기 때문 — **프롬프트로 "바꾸지 마라"고 지시하는 것만으로는 모델이
안 지키면 그만**이라 근본 해결이 안 됐다.

이 저장소는 최근 Palantir Ontology의 Action Type 개념을 차용해 `decisions/` 삭제 금지
같은 규칙을 pre-commit 훅으로 강제하는 작업을 이미 진행했다([[decisions/사지방기간-시행착오-교훈]]
및 `scripts/pre-commit-check.py`). 이번 결정은 같은 원칙을 콘텐츠 생성 파이프라인에도
적용한 것 — "규칙을 문장으로 적어두고 지키길 바라는" 대신 "규칙을 어기면 결과물 자체가
안 나가게" 만드는 방향으로 통일했다.

## 어떻게 구현했나

1. **생성 직후 강제 덮어쓰기** (`generate_daily_post.py`, `enforce_cover_headline`):
   Claude 응답을 파싱한 직후 `cover["headline_main"] = topic["title_main"]`으로 무조건
   덮어쓴다. Claude가 뭘 썼든 버려진다.
2. **내보내기 직전 최종 게이트** (`assert_cover_headline_matches`): PNG·JSON을 쓰기
   직전에 headline_main과 title_main이 정확히 같은지 다시 확인한다. 실패하면 어떤
   파일도 쓰지 않고 `sys.exit(1)`로 중단한다 — 게시물이 "일단 나가고 나중에 고치는"
   경로 자체를 차단.
3. **잠금값을 결과물에 동봉**: `post_content.json`에 `_locked_headline`(title_main
   원본)을 같이 기록한다. 생성 시점엔 항상 `headline_main`과 같지만, 이후 사람이
   `tools/bodetail_editor.html`로 표지 문구를 손으로 고쳐도 이 값은 안 바뀌므로
   **생성 이후의 변조까지 잡을 수 있는 기준선**이 된다.
4. **pre-commit 훅 연동** (`scripts/check_post_consistency.py` →
   `scripts/pre-commit-check.py`): `posts/`는 용량 문제로 `.gitignore` 처리돼 있어
   "스테이징된 파일 검사" 방식으로는 걸리지 않는다 — 그래서 git 스테이징 여부와
   무관하게 매 커밋마다 작업 디렉터리의 `posts/latest/post_content.json`을 직접 읽어
   `headline_main == _locked_headline`을 검사한다. 없으면 통과, 불일치면 커밋 차단.

## 검증 (2026-08-19)

- `generate_daily_post.py`에서 실제 함수(`enforce_cover_headline`,
  `assert_cover_headline_matches`)를 AST로 추출해 실행 — Claude가 임의로 다른
  문구를 냈다고 가정한 입력에서도 `title_main`으로 강제 고정됨을 확인. 최종 게이트가
  불일치를 `sys.exit(1)`로 정상 차단하는 것도 확인.
  (ANTHROPIC_API_KEY 등 유료 API 키가 이 환경에 없어 파이프라인 전체를 실제로
  돌리지는 못했다 — 순수 함수 로직만 분리 검증했다는 한계는 남는다.)
- 정상 케이스(`headline_main == _locked_headline`)의 `post_content.json`을 만들어
  `scripts/check_post_consistency.py`가 통과시키는 것을 확인.
- `headline_main`만 다르게 변조한 케이스를 만들어 같은 체커가 실패로 잡아내는 것을
  확인. 이어서 실제로 `git commit`을 시도해 **`posts/`가 gitignore 대상임에도**
  pre-commit 훅이 변조를 감지해 커밋을 차단하는 것까지 확인(HEAD 불변, 커밋 미생성).
  테스트에 쓴 가짜 `posts/latest/`는 실제 생성물이 아니므로 검증 후 삭제했다.
