PART A

온톨로지란? 우리 구조의 특징·규칙

코드를 짜기 전에 "무엇을 만드는지" 먼저 이해하면 훨씬 쉬워진다. 5분만 읽자.

온톨로지 = "내 데이터를 정리하는 약속(규칙)"

어렵게 들리지만 간단하다. 온톨로지는 "내 사업의 정보를 어떤 객체로 나누고, 객체끼리 어떻게 연결할지 정한 지도"다. 우리는 콘텐츠(릴스/게시물)를 만들고 그 반응을 쌓는데, 그냥 쌓으면 뒤죽박죽이다. 온톨로지가 있으면 "이건 훅 객체, 이건 주제 객체, 이 콘텐츠는 저 훅을 썼다"처럼 구조화되어, 나중에 "어떤 훅이 잘 먹혔나"를 한눈에 본다.

왜 이게 무기인가: 콘텐츠가 100개, 500개 쌓이면 머리로 기억 못 한다. 온톨로지로 쌓으면 "물어뜯기 주제 + 충격질문 훅 + 비포애프터 포맷이 저장률 6%로 최고"라는 패턴이 데이터로 나온다. 경쟁사는 감으로 하지만 우리는 데이터로 한다. 이게 시간이 갈수록 복리로 쌓이는 해자다.

우리 온톨로지의 5가지 객체(Entity)

객체뜻예시
Content릴스/게시물 1개"20년 뜯은 손톱 4주 기록"
Hook첫 3초 유형충격질문 / 공감고백
Format영상 구성 방식비포애프터 / 길거리투표
Topic주제(부위·페인)물어뜯기 / 셀프젤손상
Episode부위별 시즌EP1 손톱 / EP2 입술

각 Content는 자기가 어떤 Hook·Format·Topic·Episode를 썼는지 링크로 연결된다. 이 연결이 온톨로지의 핵심이다.

객체화(objectification)란?

"객체화"는 각 정보를 노트 1개로 만들고, 그 노트 머리에 속성(frontmatter)을 붙이는 것이다. 예를 들어 릴스 하나를 노트로 만들고 머리에 "저장률 0.05, 훅=충격질문"이라고 적으면, 그 노트가 하나의 "객체"가 된다. Dataview가 이 속성들을 읽어 표로 만들어준다.

3가지 규칙 (꼭 지킨다)

규칙 1콘텐츠 1개 = 노트 1개. 절대 한 노트에 여러 콘텐츠 섞지 않는다.
규칙 2입력변수는 발행 즉시 손으로 기록. 훅·포맷·주제·제작방식(real/ai)은 플랫폼이 안 알려주니 내가 적는다.
규칙 3성공 판정은 저장률 기준. save_rate ≥ 0.04 + 도달 중앙값 이상 → 성공 폴더. (재구매 선행지표)
"객체·연결·규칙" 개념이 머리에 들어왔다. 이제 만들러 가자.
PART B

Obsidian 설치

온톨로지를 담을 그릇(앱)을 깐다.

🪟 Windows
  1. 브라우저 주소창에 obsidian.md 입력 → 접속
  2. 화면 중앙(또는 우상단)의 Download 버튼 클릭 → Windows용이 자동 선택됨
  3. 다운로드된 Obsidian-x.x.x.exe 더블클릭
  4. 설치 진행(자동) → 완료되면 Obsidian이 자동 실행
🍎 Mac
  1. 브라우저에 obsidian.md → 접속
  2. Download 클릭 → .dmg 파일 다운로드
  3. 받은 .dmg 더블클릭 → Obsidian 아이콘을 Applications 폴더로 드래그
  4. Launchpad에서 Obsidian 실행 ("확인되지 않은 개발자" 뜨면 열기)
Obsidian 첫 화면(보관소 만들기 창)이 떴다.
PART C

Vault 만들기 + 폴더 구조 짓기

Vault(보관소)는 우리 온톨로지가 사는 폴더다. 제공한 LIBUNNY-VAULT.zip을 쓰거나, 직접 만든다. 둘 다 설명한다.

방법 ① 제공된 vault 쓰기 (빠름, 권장)
  1. LIBUNNY-VAULT.zip 파일을 마우스 우클릭 → 압축 풀기 (Windows) / 더블클릭 (Mac) → 문서(Documents) 폴더 같은 기억하기 쉬운 곳에 풀기
  2. Obsidian 첫 화면에서 Open folder as vault 클릭
  3. 파일 탐색기가 열리면 방금 푼 LIBUNNY-VAULT 폴더를 선택 → 폴더 선택
  4. "Trust author and enable plugins?" 창이 뜨면 Trust author and enable plugins 클릭
왼쪽에 0_System, 1_Content… 폴더가 보인다. → PART D로.
방법 ② 직접 만들기 (구조를 손으로 익히고 싶다면)
  1. Obsidian 첫 화면에서 Create new vault 클릭
  2. Vault name에 LIBUNNY-VAULT 입력
  3. Location 옆 Browse → 저장할 위치(문서 폴더) 선택
  4. Create 클릭 → 빈 vault 생성
  5. 왼쪽 파일 영역에서 폴더 아이콘(새 폴더) 클릭 → 아래 폴더들을 하나씩 만든다:
# 만들 폴더 (왼쪽에서 새 폴더 버튼으로 하나씩)
0_System
1_Content
1_Content/_Inbox
1_Content/Success
1_Content/Fail
2_Patterns
2_Patterns/Hooks
2_Patterns/Formats
2_Patterns/Topics
2_Patterns/Episodes
3_Products
4_Analytics
_Templates
하위 폴더 만들기: 폴더 이름에 /를 넣으면 자동으로 하위 폴더가 된다. 예: 새 폴더 이름을 1_Content/_Inbox로 입력하면 1_Content 안에 _Inbox가 생긴다.
왼쪽에 위 폴더 구조가 다 보인다.

우리 폴더 구조의 의미

0_System규칙·스키마·대시보드 (뇌)
1_Content콘텐츠 노트들. _Inbox(대기)→Success/Fail로 이동
2_PatternsHook·Format·Topic·Episode 패턴(재사용 객체)
3_Products제품 정보·메시지 규제 가드
4_Analytics주간 집계·raw 백업
_Templates새 노트 찍어내는 틀
PART D

플러그인 설치 (Dataview · Git)

대시보드가 작동하려면 Dataview가, 백업 자동화엔 Obsidian Git이 필요하다.

D-1. Dataview 설치 (대시보드 엔진)
  1. 왼쪽 맨 아래 톱니바퀴(⚙ 설정) 클릭
  2. 왼쪽 메뉴에서 Community plugins (커뮤니티 플러그인) 클릭
  3. "Restricted mode"(제한 모드)가 켜져 있으면 Turn off 클릭해서 끈다
  4. Browse 클릭 → 플러그인 검색창이 열림
  5. 검색창에 Dataview 입력 → 목록에서 Dataview 선택
  6. Install 클릭 → 끝나면 Enable 클릭
  7. 설정 창 닫기
JavaScript 쿼리 켜기(중요): 설정 → Community plugins → Dataview 옆 톱니바퀴 → "Enable JavaScript Queries"를 켠다. 일부 대시보드가 이게 있어야 작동.
Dataview가 설치·활성화됨.
D-2. (선택) Obsidian Git 설치 — 자동 백업

PART H에서 Git을 설치한 뒤 이걸 쓰면, 버튼 없이도 vault가 GitHub에 자동 백업된다. 지금은 건너뛰고 PART H 후에 와도 된다.

  1. 설정 → Community plugins → Browse
  2. 검색창에 Obsidian Git 입력 → 선택 → Install → Enable
  3. 설정에서 자동 commit 주기(예: 10분)·자동 push 설정
설치만 해두고 PART H에서 연결.
PART E

객체(노트) 만들기 — 스키마 입력

이제 진짜 온톨로지를 만든다. 콘텐츠 1개를 "객체"로 찍어낸다.

E-1. 템플릿 보고 콘텐츠 노트 만들기
  1. 왼쪽에서 _Templates/콘텐츠_템플릿.md 클릭해 내용 확인(제공 vault에 있음). 없으면 아래 내용을 새 노트로 만든다.
  2. 1_Content/_Inbox 폴더 우클릭 → New note
  3. 노트 이름: R-20260616-01 (R=릴스, 날짜, 순번)
  4. 노트 맨 위에 아래를 그대로 입력 (이게 "객체의 속성"):
---  ← 이 세 줄표시가 frontmatter 시작/끝
type: content
id: R-20260616-01
status: inbox
platform: reels
episode: "[[EP1 손톱]]"
hook: "[[Hook - 충격질문]]"
format: "[[Format - 비포애프터]]"
topic: "[[Topic - 물어뜯기회복]]"
made_by: real
cta: "21일챌린지"
publish_at: 2026-06-16T20:00
views: 0
reach: 0
saves: 0
shares: 0
save_rate: 0
verdict: ""
reason: ""
---

# 여기 아래는 콘티 내용(자유롭게)
## 콘티
- 훅(0~3초):
- 전개(3~15초):
- CTA(15~25초):
frontmatter란? 노트 맨 위 ---와 --- 사이의 속성 목록. Dataview가 이걸 읽어 표로 만든다. 띄어쓰기·콜론(:) 형식을 정확히 지켜야 한다.
_Inbox에 첫 콘텐츠 객체 노트 1개 생김.
E-2. 속성 뜻 (입력값 가이드)
statusinbox(대기) → 나중에 success/fail로 바뀜
made_byreal(실촬영) 또는 higgsfield(AI)
save_ratesaves ÷ reach. 발행 후 계산해 입력
[[...]]다른 노트로 연결하는 링크. 패턴 객체와 묶인다
PART F

패턴 객체 + 관계 연결

위에서 [[Hook - 충격질문]]처럼 링크를 걸었다. 이제 그 링크가 가리킬 패턴 객체를 만든다. 이게 "객체끼리 연결"이다.

F-1. Hook 패턴 노트 만들기
  1. 2_Patterns/Hooks 폴더 우클릭 → New note
  2. 이름: Hook - 충격질문 (콘텐츠에서 링크한 이름과 정확히 같게)
  3. 아래 입력:
---
type: pattern
category: hook
title: 충격질문 훅
---
# 충격질문 훅
## 정의
첫 3초에 불안·호기심을 찌르는 질문으로 스크롤을 멈춤.
## 이 훅을 쓴 콘텐츠 (자동 집계)
```dataview
TABLE save_rate, reach, verdict
FROM "1_Content"
WHERE contains(string(hook), "충격질문")
SORT save_rate DESC
```
마법: 위 ```dataview 블록이 "이 훅을 쓴 모든 콘텐츠와 그 성과"를 자동으로 표로 만든다. 콘텐츠가 쌓일수록 이 훅이 잘 먹히는지 한눈에 보인다.
F-2. 같은 방식으로 나머지 패턴 객체 만들기
  1. 2_Patterns/Formats/Format - 비포애프터
  2. 2_Patterns/Topics/Topic - 물어뜯기회복
  3. 2_Patterns/Episodes/EP1 손톱

각각 type/category만 바꾸고 같은 구조로. (제공 vault엔 이미 들어있음)

콘텐츠 노트의 링크를 클릭하면 패턴 노트로 이동된다 = 객체가 연결됨.

에피소드(부위) 객체 — 우리만의 특화

Episode 객체는 "신체 부위 시즌"이다. EP1 손톱 → EP2 입술 → EP3 발… 각 콘텐츠가 어느 에피소드인지 태깅하면, 어느 부위 콘텐츠가 반응이 좋은지 데이터로 나와서 "다음에 뭘 제품화할지"를 수치로 정한다.

# EP 객체에 넣을 dataview (이 부위 콘텐츠 성과 집계)
```dataview
TABLE save_rate, topic, verdict
FROM "1_Content"
WHERE contains(string(episode), "손톱")
SORT save_rate DESC
```

PART H

Git 설치 + GitHub 백업

vault가 컴퓨터 고장으로 날아가면 끝이다. GitHub에 백업한다.

H-1. Git 설치
🪟 Windows
  1. 브라우저 → git-scm.com/download/win → 자동 다운로드
  2. 받은 설치파일 실행 → 모든 옵션 기본값으로 Next 반복 → Install
  3. 시작 메뉴 → cmd 검색 → 명령 프롬프트 열기
  4. git --version 입력 → 버전 뜨면 성공
🍎 Mac
  1. Launchpad → 터미널 검색해 열기
  2. git --version 입력
  3. 설치 팝업 뜨면 설치 클릭
  4. 다시 git --version 확인
H-2. Git 첫 설정

cmd(터미널)에 한 줄씩:

git config --global user.name "본인이름"
git config --global user.email "가입한Gmail주소"
H-3. GitHub 레포 만들기
  1. 브라우저 → github.com 로그인
  2. 우상단 + → New repository
  3. Repository name: libunny-vault
  4. Private 선택 (비공개)
  5. Create repository 클릭
  6. 다음 화면에 나오는 https://github.com/...libunny-vault.git 주소 복사해둠
H-4. vault를 GitHub에 올리기 (첫 push)

cmd(터미널)에서 vault 폴더로 이동 후 한 줄씩:

# vault 폴더로 이동 (경로는 본인 위치에 맞게)
cd Documents/LIBUNNY-VAULT

git init
git add .
git commit -m "first backup"
git branch -M main
git remote add origin [H-3에서 복사한 주소]
git push -u origin main
  1. 마지막 줄에서 브라우저 인증창이 뜨면 GitHub 로그인 → 허용
  2. GitHub 레포 페이지 새로고침 → vault 파일들이 올라와 있으면 성공
이후 백업은 3줄: git add . → git commit -m "update" → git push. 또는 D-2의 Obsidian Git 플러그인이 자동으로 해준다.
GitHub에 vault가 백업됨. 컴퓨터 날아가도 안전.
PART I

Antigravity + 분류 스크립트

지표를 보고 성공/실패를 자동으로 나누는 단계. 코딩 못 해도 자연어로 시킨다.

I-1. Antigravity 설치
  1. 브라우저에 Antigravity Google 검색 → 공식 다운로드 페이지 접속
  2. OS에 맞는 설치파일 다운로드 → 실행 → 설치
  3. 실행 → Google 계정(가입한 Gmail)으로 로그인
  4. Open folder → LIBUNNY-VAULT 폴더 열기
못 찾겠으면? VS Code(code.visualstudio.com) + Python으로 대체 가능. "파이썬 실행 환경"이면 무엇이든 OK.

# Antigravity에 시킬 말 (복붙)
LIBUNNY-VAULT/1_Content/_Inbox 폴더의 .md 노트들을 읽어서,
frontmatter의 save_rate가 0.04 이상이고 reach가 나머지
노트들의 중앙값 이상이면 status를 success로, 아니면 fail로
바꾸고, 각각 1_Content/Success 또는 1_Content/Fail 폴더로
옮기는 파이썬 스크립트를 만들어서 실행해줘.
python-frontmatter 라이브러리를 사용해.
  1. Antigravity가 코드를 만들어 보여줌 → 실행(Run)
  2. 에러가 나면 그 에러 메시지를 복사해서 다시 붙여넣고 "이 에러 고쳐줘"

AI 사용감 핵심: 코드를 몰라도 된다. "시키고 → 실행 → 에러 붙여넣고 고치고"의 반복이 곧 AI 협업 훈련이다. 이 경험 자체가 준비기간의 목적이다.
