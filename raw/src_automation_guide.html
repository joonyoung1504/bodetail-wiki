Bodetail · Content Automation · 고도화판 v2

콘텐츠 자동화 구축 가이드

9객체 온톨로지 + 메타 API 자동 수집 + 통계 신뢰 장치. Claude Code가 인스타 지표를 자동으로 끌어와 분류·분석하고, 성공 방정식을 찾아 다음 콘티를 맞춤 제작한다. 게시만 직접.
이 파일만 보고 위에서부터 따라 하면 됩니다 · 복사 버튼으로 명령·지시문을 그대로 붙여넣으세요 · 5대 보완(API자동수집·통계신뢰·변수압축·발행큐·노이즈제거) 반영

전체 순서

  1. 준비물 설치 (한 번만)
  2. 작업 폴더 + 미래 전환 대비 구조
  3. 세밀 지표 사전 — 마케터가 보는 모든 것
  4. 메타 API 연동 — 지표 자동 수집 ★신규
  5. 고도화 온톨로지 — 9객체 + 관계 규칙
  6. 변수를 객체로 — 핵심 변수 압축 + 기록
  7. 통계 신뢰 장치 — 우연을 성공으로 착각 않기 ★신규
  8. 콘티 자동 제작 + 발행 큐
  9. 반응 자동 수집 + 분석 + 성공방정식
  10. GitHub 백업
  11. 발행 (직접) + 나중에 하이브리드
이 버전이 "진짜 세컨드 브레인"에 가까워진 이유. 이전 설계의 5대 결함을 보완했다 — ① 메타 API 자동 수집(수작업 입력 제거) ② 통계 신뢰 장치(우연을 성공으로 착각 방지) ③ 핵심 변수 압축(40개→7개, 검증 가능하게) ④ 발행 큐(결과 대기 후 반영, 루프 안 끊김) ⑤ 노이즈 제거(이상치 표시). 이제 데이터가 알아서 흘러들어와 성공 방정식을 찾는다.
단, 솔직한 전제 2가지. ① 메타 API 인사이트는 팔로워 1,000명 이상 + 비즈니스/크리에이터 계정 + 페이스북 페이지 연결이 필요하다(개인 계정 불가). 1,000명 전까지는 수동/스크린샷 입력으로 가다가, 1,000명 넘으면 API 자동으로 전환. ② 3초 잔존곡선 같은 일부 진단 지표는 API로 안 나와 앱에서 보조 입력해야 한다. 그래서 "API 자동 + 스크린샷 보조"의 하이브리드가 현실 정답이다.

2 METRICS

세밀 지표 사전 — 마케터가 보는 모든 것

조회·저장·팔로우만 보면 초보다. 인스타 알고리즘이 실제로 중요하게 보는 지표와, 마케터가 추적하는 디테일을 전부 기록한다. 가중치: 높음 중간 낮음

지표의미 · 왜 중요가중치

avg_watch_time 평균시청평균 몇 초 봤나(길수록 좋음)높음

3 META API ★신규

메타 API 연동 — 지표 자동 수집

수작업 입력을 없애는 핵심 단계. AI 에이전트가 인스타 지표를 자동으로 끌어와 frontmatter에 채운다. 단 설정 장벽이 있어, 순서대로 따라가야 한다.

전제 조건(필수). ① 인스타를 비즈니스 또는 크리에이터 계정으로 전환 ② 페이스북 페이지 생성 후 연결 ③ 인사이트 지표는 팔로워 1,000명 이상부터 제공. 1,000명 전이라면 이 단계는 건너뛰고, 6단계의 "스크린샷/수동 입력"으로 가다가 나중에 전환한다.

① 메타 개발자센터 세팅 (한 번만)

  • developers.facebook.com 접속 → 개발자 등록 → 앱 만들기(유형: 비즈니스)
  • 제품 추가에서 Instagram Graph API 선택
  • 인스타 비즈니스 계정 ↔ 페이스북 페이지 연결 확인
  • 장기 액세스 토큰(Long-lived token) 발급 — 60일 유효, 갱신 필요
  • 발급한 토큰·계정 ID를 config/secrets.env에 저장(이 파일은 절대 GitHub에 올리지 않음 → .gitignore 처리)
보안 — 토큰은 비밀번호와 같다. 토큰을 코드나 공개 파일에 적지 말 것. config/secrets.env에만 두고, .gitignore에 추가해 GitHub에 안 올라가게 한다. (아래 지시문에 포함)

② Claude Code에 수집 스크립트 만들기

scripts/에 메타 API 지표 자동수집 모듈을 만들어줘. 1. config/secrets.env에서 액세스 토큰·IG 계정 ID를 읽어온다(이 파일은 .gitignore에 추가해 GitHub에 안 올라가게). 2. 내 인스타 미디어 목록을 가져와, 각 미디어의 insights를 호출: - 공통: views, reach, saved, shares, likes, comments - 릴스 추가: reels_skip_rate(건너뛰기율), 그리고 가능한 재생/완주 관련 지표 - 계정 단위: follower_count, reach 주의: impressions·video_views는 deprecated라 views를 쓴다. 3. 가져온 값을 해당 content/ 파일의 frontmatter 지표 필드에 자동 기록하고, 사용 Variant의 누적 성과도 갱신. 4. API로 안 나오는 지표(3초 잔존율, 구간 이탈곡선, 도달출처 세부)는 따로 표시해서, 내가 앱 스크린샷으로 보조 입력할 수 있게 빈 칸으로 남겨줘.

4 ONTOLOGY

고도화 온톨로지 — 9객체 + 관계 규칙

단순 5객체를 넘어 변수·실험·학습까지 객체로 분리. "비슷한 것끼리 묶고, 인과를 분리"하는 게 목표.

#객체역할관계
1Content콘텐츠 1개. 변수값·지표가 모이는 중심아래 객체들을 [[링크]]
2Episode연재 회차/세계관(EP1→EP2…)Content 다수 포함
3Topic주제(손톱/물어뜯기/디테일/입술/발)Episode·Content와 연결
4Hook후킹(충격질문/비포애프터/공감/반전/숫자)Content가 1개 참조
5Format형식(릴스/캐러셀/스토리+길이대)Content가 1개 참조
6Variable ★실험 변수 정의("무엇을 바꿀 수 있나"의 사전)Variant들을 가짐
7Variant ★변수의 구체 값("어떤 값이 이겼나"가 쌓임)여러 Content가 공유 참조
8Experiment ★실험 1건(가설+바꾼변수+대조군+결과)Content들을 비교군으로
9Insight ★검증된 학습(예: "빨간 자막 +30%")Experiment서 도출, 새 Content에 반영

★ = 이번에 새로 승격. 변수(6·7)·실험·학습(8·9)이 독립 객체가 되며 "어떤 변수의 어떤 값이 왜 이겼나"가 Obsidian에 영구히 쌓인다.

[ 데이터 흐름 ] Episode ─┬─ Topic ── Hook ── Format │ Content ◀── Variant ◀── Variable (콘텐츠가 어떤 변수값을 썼나) │ ▲ ▼ │ [지표 기록] Experiment ── Insight (실험으로 변수값 승패 → 학습) │ │ └──── Dataview 집계 ◀──────┘ (학습이 다음 Content에 반영)

관계 규칙 (온톨로지가 "규칙대로 움직이게")

  • R1. 모든 Content는 Episode·Topic·Hook·Format을 각 1개씩 [[링크]](필수).
  • R2. 모든 Content는 사용한 Variant들을 frontmatter variants: 목록에 [[링크]].
  • R3. 한 Experiment의 Content들은 딱 하나의 Variable만 다르고 나머지 동일(인과 분리).
  • R4. Experiment 종료 시 이긴 Variant 판정 → Insight 기록(status: validated).
  • R5. 새 Content 생성 시 validated Insight를 기본값 적용(학습 반영).
  • R6. 모든 객체 frontmatter에 type:을 달아 Dataview가 종류별 집계 가능하게.
▸ Claude Code에 붙여넣기
ontology/ 폴더에 9객체 온톨로지를 만들어줘. (각 객체 type 필드 포함) 1 Content : 콘텐츠 1개. variants 링크와 지표가 모이는 중심 2 Episode : 연재 회차/세계관. Content 다수 포함 3 Topic : 주제 4 Hook : 후킹 방식 5 Format : 형식+길이대 6 Variable : 실험 변수 정의 7 Variant : 변수의 구체 값. 여러 Content가 공유 참조 8 Experiment : 실험 1건(가설+바꾼변수+대조군+결과). 한 번에 한 변수 9 Insight : 검증된 학습. Experiment서 도출, 새 Content에 반영 [관계 규칙] R1 Content는 Episode/Topic/Hook/Format 각 1개 [[링크]](필수) R2 Content는 사용 Variant들을 frontmatter variants: 목록에 [[링크]] R3 한 Experiment의 Content들은 Variable 딱 하나만 다르고 나머지 동일 R4 Experiment 종료 시 이긴 Variant 판정 → Insight(status: validated) R5 새 Content 생성 시 validated Insight 기본 적용 R6 모든 객체 frontmatter에 type 필드 각 객체 템플릿 .md(frontmatter 포함)와 ontology/README.md(관계 설명)를 만들어줘. Content 템플릿 frontmatter에는 다음 단계의 변수 필드 + 지표 필드(A~D 전체)를 모두 포함.
5 VARIABLES

변수를 객체로 — 핵심 변수 압축 + 기록

질문의 핵심이었던 부분. 변수를 태그가 아니라 Variable(정의)+Variant(값) 객체로 만들어 Obsidian에 영구 기록한다. 단 보완: 변수를 다 동시에 실험하지 않는다.

보완 — 변수 과다 함정 해결. 변수 40개를 한 번에 한 개씩 검증하려면 콘텐츠 수백 개가 필요해 1인 창업자는 불가능하다. 그래서 전체 변수는 사전으로 보관하되, 실제 실험은 영향 큰 "핵심 7개"부터 돌린다. 나머지는 "나중 여유 시" 칸으로.

핵심 변수 7개 (이것부터 실험)

우선Variable왜 영향 큰가
1hook_type도입 후킹 — 3초 이탈을 좌우(완주율 직결)
2first3sec_scene첫 3초 장면 — 알고리즘 부스팅의 관문
3opening_line첫 자막/멘트 — 시선 잡는 한 문장
4caption_copy본문 카피 — 저장·공유 유도
5cta_type행동유도(저장/공유/팔로우) — 전환 직결
6publish_time발행 시각 — 초기 1시간 반응 좌우
7topic주제 — 애초에 먹히는 소재인가

나머지 변수(자막색·폰트·BGM·전환·줌 등)는 사전에 정의만 해두고, 핵심 7개가 안정된 뒤 실험한다.

그룹Variable (변수)

▸ Claude Code에 붙여넣기
variables/ 와 variants/ 폴더에 변수 시스템을 만들어줘. 1. 위 표 모든 factor를 각각 Variable 노트로 생성(variables/var_caption_color.md 식). frontmatter: type: variable, group, description, hypothesis(영향 가설). 2. 각 Variable에 자주 쓸 Variant(값) 노트를 미리 몇 개씩(variants/, 예: variant_caption_color_red/_white/_yellow). frontmatter: type: variant, parent_variable, value, 누적집계 필드(used_count, avg_save_to_reach, avg_completion 등 — Dataview가 채움). 3. content/ 템플릿이 R2 규칙대로 variants: [[...]] 목록으로 사용 변수값을 링크하게. 4. 모든 지표(A~D)를 Content frontmatter 필드로 포함: A: saves, shares, sends_dm, completion_rate, avg_watch_time, rewatch_rate, comments, likes B: views_1h, views_24h, saverate_1h, eng_velocity, first_hour_reach C: reach, impressions, reach_follower, reach_nonfollower, source_explore/home/reels/hashtag/audio/profile, follows_from_post, profile_visits, profile_visit_rate, link_clicks, sticker_taps D: hook_retention_3s, retention_curve, drop_off_point, save_to_reach, share_to_reach 파생지표 계산식은 주석으로. 5. experiments/ 폴더: Experiment 템플릿(가설/바꾼 Variable 1개/대조군 Content들/결과/이긴 Variant/도출 Insight) + README(R3 한번에 한 변수 규칙).
R3 — 한 번에 한 변수만. 자막색과 BGM을 동시에 바꾸면 뭐 때문에 올랐는지 모른다. Experiment는 항상 하나의 Variable만 바꾸고 나머지 고정. 핵심 7개부터 순서대로 실험하면 표본이 빨리 쌓인다.
6 STATISTICS ★신규

통계 신뢰 장치 — 우연을 성공으로 착각하지 않기

콘텐츠 3개로 "빨간 자막이 +30%"라고 믿으면 위험하다. 우연일 수 있다. 표본·신뢰도·이상치를 관리해 진짜 성공 방정식만 채택한다.

3가지 안전장치

장치규칙
최소 표본Variant별 sample_size 기록. 5개 미만=참고용, 10개 이상=신뢰. 표본 적으면 결론 보류
학습 단계Insight에 status: hypothesis → testing → validated 3단계. 표본·격차 충분해야 validated 승격
이상치 제거성과가 평균의 N배 이상이거나 외부요인(인플루언서 공유 등) 있으면 anomaly_note 기록 → 성공방정식 계산에서 제외/가중치 조정
▸ Claude Code에 붙여넣기
통계 신뢰 장치를 시스템에 추가해줘. 1. Variant 노트에 sample_size, confidence 필드 추가. Dataview가 그 변수값을 쓴 Content 수를 세서 sample_size를 자동 갱신. 2. Insight 노트에 status: hypothesis / testing / validated 3단계 + 판정 규칙: - sample_size 5 미만 → hypothesis(참고용) - 5~9 → testing - 10 이상 AND 1·2위 Variant 성과격차가 뚜렷 → validated 승격 가능 3. Content에 anomaly_note 필드와 is_outlier(true/false) 추가. 성과가 같은 조건 평균의 3배 넘거나 외부요인 메모가 있으면 is_outlier=true로 표시. 4. 집계·분석 시 is_outlier=true인 Content는 성공방정식 계산에서 제외(또는 별도 표시)하게 해줘. 5. queries/에 "아직 표본 부족해 결론 못 내린 변수 목록"과 "validated된 성공공식" 쿼리를 추가.
이로써 2·5번 결함 해결. 표본이 부족하면 "아직 모름"으로 남고, 우연한 대박(이상치)은 방정식에서 빠진다. 잘못된 성공공식을 믿고 엉뚱하게 가는 걸 막는다.
7 CREATE

콘티 자동 제작 + 발행 큐

콘티를 만들면 변수·실험이 자동 기록된다. 보완: 발행 큐로 "결과 대기 후 반영"해 루프가 끊기지 않게 한다.

보완 — 발행 큐(4번 결함 해결). 콘티를 만들고 바로 다음 콘티를 또 만들면, 직전 결과가 반영되기 전에 새 게 나가 루프가 끊긴다. queue/로 상태를 관리한다: 대기 → 발행됨 → 결과수집중 → 분석완료. "같은 변수 실험은 직전 결과가 들어온 뒤에만" 진행한다.
▸ Claude Code에 붙여넣기
바디테일 인스타 릴스 콘티를 3개 만들어 content/에 저장하고, queue/에 발행대기로 등록해줘. - topic: 남자 손톱 첫인상 / 물어뜯는 습관 / 손끝 디테일 - 온톨로지 규칙대로: Episode/Topic/Hook/Format 각 1개 [[링크]], 사용 Variant들을 variants: 목록에 [[링크]] - 이번 Experiment: 핵심 변수 중 hook_type "딱 하나만" 다르게, 나머지 동일 → experiments/에 Experiment 노트 생성, 가설 기록 - 본문: 첫3초 장면, 컷 구성, 자막 문구, BGM 방향, CTA, 첫댓글안, 썸네일안 - 지표 필드는 비워둠(발행 후 API가 채움) - queue 상태: 대기. "직전 같은변수 실험 결과가 들어오기 전엔 동일변수 실험 안 함" 규칙 적용 - 규제: '치료·완치·회복' 금지 → '관리·보습·정돈·디테일'. 효능 단정 금지.
변수 기록까지 자동인 이유: 콘티 생성 시 AI가 R2에 따라 사용 Variant를 자동 링크하고, Experiment 노트에 "이번엔 hook만 바꿈"을 기록한다. 즉 콘티 제작과 동시에 "무엇을 변수화했는지"가 온톨로지에 저장된다 — 빠졌던 부분이 채워졌다.
8 ANALYZE

반응 자동 수집 + 분석 + 성공방정식

① 지표 자동 수집 (4단계 API 모듈)

발행했으면 "지표 수집해줘" 한마디로 API가 모든 콘텐츠 지표를 갱신한다(4단계에서 만든 모듈). 1,000명 미만이면 스크린샷 보조 입력.

▸ Claude Code에 붙여넣기
지표 수집해줘. API로 모든 content/의 views·reach·saved·shares·likes·comments·reels_skip_rate를 갱신하고, 사용 Variant의 누적 성과와 sample_size도 갱신해줘. API로 못 가져온 진단 지표(3초 잔존율·이탈지점·도달출처)는 목록으로 알려줘.

→ 진단 지표는 앱 인사이트 스크린샷을 첨부해 "이 스크린샷에서 읽어 채워줘"로 보조 입력(4단계 ④ 참고).

② 자동 집계 (Obsidian)

▸ Claude Code에 붙여넣기
queries/ 폴더에 Dataview 쿼리 노트를 만들어줘: 1 Variant별 평균 save_to_reach·completion·sends_dm 순위(어떤 값이 이기나) 2 hook_type별 / 발행시각별 / 자막색별 평균 성과 3 초기 1시간 지표(saverate_1h)와 최종 reach의 상관(초기반응이 떡상 예측하나) 4 도달출처 분포 평균(탐색에서 터지나 해시태그에서 터지나) 5 Experiment별 결과 요약 + 아직 Insight 안 뽑은 실험 목록 6 validated Insight 목록(현재까지 검증된 성공공식)
온톨로지가 "규칙대로 움직인다"는 증거: 사람이 분류 안 해도 type·링크·frontmatter 규칙 덕에 Dataview가 Variant별·출처별·실험별로 자동 집계. 쌓일수록 "성공 방정식"이 또렷해진다.

③ 학습 → 다음 콘티

▸ Claude Code에 붙여넣기
지금까지 content/ 전체와 queries/ 집계를 분석해줘. - validated된 Insight(표본 10+, 격차 뚜렷)만 "확정 성공공식"으로 정리. testing/hypothesis는 "아직 검증 중"으로 구분 - is_outlier=true인 콘텐츠는 계산에서 제외하고, 제외했다고 알려줘 - 확정된 성공공식을 기본 적용해 다음 릴스 콘티 3개 생성(R5) + queue 등록 - 다음 Experiment는 핵심 7변수 중 아직 검증 안 된 것 하나만 바꿔 설계(R3) - 표본 부족해 결론 못 낸 변수도 목록으로 알려줘

10 PUBLISH

발행 — 직접 + 나중에 하이브리드

지금은 게시만 직접. Claude Code가 만든 콘티·영상을 인스타 앱에서 직접 업로드(1분). 가장 빠르고 안 막힌다. 자동 발행은 비즈니스계정·페북연결·앱검수가 필요해 검증 후로.
