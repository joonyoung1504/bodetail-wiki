# bodetail 자동화 시스템 구축 전체 기록
> Claude AI 채팅 전체 요약 (사지방 기간, 2026-07 ~ 2026-08)
> Claude Code에게: 이 파일을 근거로 marketing_auto/, decisions/ 에 지식화할 것.
> "무엇을 만들었나"뿐 아니라 "왜 이렇게 결정했는지", "어떤 시행착오를 거쳤는지",
> "아직 해결 안 된 것"을 반드시 함께 기록할 것.

## 0. 배경

- 준영은 전역 전 사지방(브라우저 전용, 로컬 개발환경 없음) 환경에서 이 모든 작업을 진행함.
- 이 기간 동안 GitHub 웹 UI로만 코드를 커밋했고, Claude Code나 옵시디언 볼트와 연동이 끊겨 있었음.
- 이 문서는 그 공백 기간의 판단 근거와 시행착오를 복원하기 위한 것.
- 이후 휴가 복귀 + 집 PC 확보로 Claude Code 재사용 가능해짐 → 이 파일을 근거로 볼트 재동기화 중.

## 1. bodetail 마스터플랜 (사업 전략)

**1차 (간단 버전):** 시장 판단(국내 남성 그루밍 시장 1.1조, 연 3% 성장 — 느림 / 글로벌 남성 그루밍 시장 크고 빠름), bodetail의 구조적 무기(콘텐츠 한계비용 0, 롤온 폼팩터 차별화, 포지셔닝 공백), Phase 0~4 로드맵, 엑시트 시나리오(구다이글로벌형 애그리게이터 1순위).

**2차 (완전판, PDF 16페이지):** "너무 구체적이지 않다"는 피드백으로 재작성.
- Part 2: 팔로워 성장 사다리 0→1K→10K→5만→10만→30만, 각 구간 알고리즘 특성·업로드 주기·전술
- Part 4: 2026.07~2028.12 **월별** 실행 캘린더 (30개월) + 2029~2031 분기별
- Part 5: 런칭 D-30~D+30 일 단위 플레이북
- Part 6~10: 커머스 설계, 마케팅 프로그램, 재무 모델, 엑시트 설계, 리스크 매트릭스
- 핵심 원칙: "게이트 조건 통과 못 하면 다음 단계로 안 넘어간다"

**저장 위치 제안:** `brand/masterplan-v2.pdf` 또는 `brand/`

## 2. bodetail Daily Post Generator (게시물 자동화) — 사고와 복구의 연속

### 2-1. 최초 문제: 주제가 매일 반복됨 (버그 #1)
- 원인: `datetime(2026, 9, 15)` 라는 **미래 날짜**를 기준일로 잡아서 `elapsed = (TODAY - start_date).days`가 항상 음수/0 → `day_num`이 영원히 1로 고정.
- **해결책 합의**: 날짜 계산 대신 `posts/topic_state.json`에 `last_day`를 저장하고 매 실행마다 +1 하는 방식으로 전환하기로 함. (이 시점엔 아직 실제 코드는 못 받은 상태 — 형이 파일 안 줌)

### 2-2. 대형 사고: 파일 덮어쓰기 (리버니 네일 스크립트가 bodetail 자리에)
- 형이 GitHub Actions "성공(초록불)"인데 `posts/`에 아무것도 안 생기는 상황 보고.
- 로그 분석: `git add posts/`만 하는데 스테이징할 게 없어서 "변경 없음"으로 통과.
- 원인 진단: `generate_daily_post.py`를 열어보니 **리버니 네일룸 생성기 코드**가 들어있었음. 사지방에서 복붙하다가 실수로 다른 프로젝트 코드를 덮어씀.
- 복구: GitHub 파일 History에서 커밋 `4763868`(7/6 사고 이전 마지막 정상본)을 찾아 Raw로 복사 → 원본 확보.
- **재발 방지 규칙 수립**: "파일 첫 5줄 확인 — bodetail 파일은 `bodetail 일일 게시물 완전 자동화`로 시작해야 함. '리버니'가 보이면 잘못된 파일."

### 2-3. 주제 순환 시스템 정식 구현
- `posts/topic_state.json`에 `last_day` 저장, 매 실행 `(last_day % total) + 1`로 순환.
- `day_override` 있으면 상태 파일 안 건드리고 그 번호만 생성(수동 재생성용).
- 30일 소진 시 마지막 주제 생성 후 자동으로 **다음 30일 배치를 Claude가 생성**하는 `refresh_topics_batch()` 함수 추가. 실패해도 기존 배치로 안전하게 재순환(예외 처리).
- 범위 밖 DAY 번호(예: 40 입력 시 목록에 없음) 입력 시 조용히 DAY1로 폴백하던 버그 발견 → 자동 순환 매핑 + 경고 로그로 수정.

### 2-4. 커스텀 주제 기능 추가
- Actions workflow_dispatch에 `custom_topic`, `custom_desc`, `custom_section` 입력 추가.
- 비워두면 자동 순환, 채우면 그 주제로 생성(day00 폴더, VOL 대신 SPECIAL 표기, 상태 파일 안 건드림).
- 창업자 지침(`custom_desc`)은 프롬프트에 "★★ 최우선 반영" 태그로 주입.

### 2-5. 콘텐츠 품질 문제 — "너무 뻔하다"는 지적과 개선
형이 실제 생성물을 보고 "누구나 아는 얘기다, 꿀팁이 아니다"라고 강하게 지적함. 예시로 원하는 수준을 상세히 제시(세럼/앰플 차이, 도포법+대기시간, 팩 종류·시간, PX 추천, 가성비 시술 등).

**해결책 — 3단계로 구조화:**
1. **품질 3테스트를 프롬프트에 상수로 삽입**: 검색테스트(누구나 아는 말 탈락) / 구체성테스트(수치·메커니즘·조건분기·성분명 중 최소 2개) / 그래서어떻게테스트(현상지적 금지, 행동까지)
2. **`content_brief` 필드 신설**: 각 주제에 "그날 반드시 다룰 구체 항목" 100자 지시문 추가. 이게 품질을 실제로 끌어올리는 핵심 장치.
3. **`topic_domains.md` 신설**: 형이 직접 편집 가능한 소재 저장고. 12개 분야(클렌징, 자외선, 기초케어, 고민별, 헤어, 체취, 운동 장비/불균형, 생활습관, 상황 등)로 정리. 배치 소진 시 이 파일을 읽어 다음 배치 자동 생성. "추가 소재 메모" 칸에 한 줄 적으면 자동 반영되는 구조.

### 2-6. 주제 생성 공식 — "형이 준 좋은 예시들의 공통 구조를 추출"
형이 여러 프롬프트에 걸쳐 예시로 준 좋은 주제들("예산없이 자기관리", "세럼 vs 앰플" 등, 특히 롤모델 계정 `iamtheserkan`, `minens.mag` 분석)을 역분석해서 `topic_formula.md` 작성.

**주제 해부학 5요소**: 분해 축 / 수치 앵커 / 혼동 지점 / 실행 종결 / 오답 제거.

**15개 원형(A1~A15)**: 분류→처방, 혼동해소(AvsB), 파라미터 완전정복, 랭킹·티어, 금지조합·경고, 상황제약 최적해, 자가진단→판정→행동, 습관→개선메커니즘(★ 형이 특히 강조한 유형), 유지·관리주기, 스위칭규칙, 제약조건형(예산없이), 인과사슬, 용어집·시리즈, 환경설계, 정체성·심리.

**제목 창의성 패턴 8종**: 제약선언, 연쇄화살표, 등식, 신조어, 상황극단, 등급차수, 역설, 숫자+정체성.

이 공식으로 실제 신규 주제 다수 생성 → 주제 배치 30일 → 42일 → 60일 → 66일로 확장.

**배치 구성 규칙**: 최소 9개 원형 등장, 같은 원형 5개 안 넘음, A5·A8·A11·A15는 배치당 최소 1개 필수.

### 2-7. 다음 편 예고 기능
- 형이 롤모델 계정(minens.mag) 분석하며 요청: 마지막 페이지에 다음 주제 예고.
- 실제 구현: 주제 파일에서 실제 다음 날짜 주제를 조회해 정확히 주입(지어내지 않음). 캡션에도 "다음 편 — ○○" 자동 추가.
- 주제 순서를 **연관 클러스터**로 재배열(원리→진단→처방→비교→추천 흐름)해서 예고가 자연스럽게 이어지도록 함.
- **버그 발견 및 수정**: 처음엔 `post_json`에 `next_preview` 필드를 안 넣어서 계산은 되는데 에디터에 안 뜨는 문제 있었음 → JSON 최상위 + 마무리 슬라이드 양쪽에 중복 삽입으로 해결.

### 2-8. 레이아웃/가독성 문제와 해결
- "글자가 너무 많다"는 지적 → 원인: 프롬프트가 정보 밀도만 요구하고 분량 상한이 없었음.
- **분량 상한 도입**: 소제목 18자 1줄, 본문 정확히 2줄×26자, 본문 1줄=사실/2줄=행동 구조, "—"로 문장 잇기 금지.
- **압축 시 "비교 기준"을 절대 버리면 안 된다는 규칙 추가**: 형이 "여성보다"를 빼면 이해 못한다고 정확히 지적 → 압축 원칙에 "절대 버리면 안 되는 것"(비교기준·수치·조건·행동동사) vs "버려야 하는 것"(수식어·접속) 리스트화.
- **텍스트 하단 정렬로 렌더러 개편**: 위에서부터 흘러내리던 구조를, 캡션 바 기준 하단 정렬로 바꿔 사진 상단이 항상 비게 함. 에디터(HTML)와 파이썬 렌더러 양쪽 다 수정 필요했음(처음엔 파이썬만 고쳐서 실효 없었음 — 최종 PNG는 에디터에서 나온다는 걸 뒤늦게 인지).

### 2-9. PICK(제품 추천) 게시물 가격 정확도 문제
- "약 2만원대" 같은 어림 표기 지적받음 → Claude가 학습 기억으로 대충 쓴 것.
- 해결: PICK 게시물 생성 시에만 `web_search_20250305` 도구를 붙여 실제 올리브영 판매가 검색 후 작성. 정확한 원 단위 표기 강제, 확인 못하면 다른 제품으로 교체.

### 2-10. 학습 루프 시스템 (규칙 증류)
- "AI처럼 매주 조금씩 발전하는 구조" 요청.
- `fetch_ig_insights.py`: Instagram Graph API로 게시물별 반응(좋아요·저장·도달) 수집. **주의: 계정 로그인 스크래핑은 메타 약관 위반+계정정지 위험이라 명시적으로 배제, 공식 API만 사용.**
- `learn_from_results.py`: 반응 데이터 + 최근 게시물 내용 + 기존 규칙을 Claude가 분석 → `content/learnings.md`를 통째로 재작성(검증된 규칙/검증중/폐기). 다음날부터 생성 프롬프트에 자동 주입.
- `weekly_learn.yml`: 매주 일요일 실행.

### 2-11. 최근 이슈 (미해결)
- DAY1에서 예고한 "다음 편" 제목과 DAY2로 실제 생성된 게시물 제목이 다름. 원인: 주제 파일 title_main은 맞는데 Claude가 표지 문구를 자기 마음대로 재작성해서 어긋남. **해결 방향 합의(A안): 표지 headline을 주제 파일의 title_main으로 고정하고 부제만 Claude가 쓰게 한다 — 아직 코드 미반영.**
- 게시물에 워터마크 박힌 스톡이미지, 의학 일러스트풍 이미지가 섞여 나온 사례 발견(살구색 피부단면도, Adobe Stock 워터마크). 브랜드 톤(잉크블랙·크림·골드 다크무드)과 완전히 이질적. **원인 미확정 — 형에게 "수동으로 넣은 거냐 자동 생성이냐" 질문한 상태에서 대화 종료. 코드 수정 안 됨.**

## 3. 게시물 편집기 (bodetail_editor.html) 진화

원래 3개 탭(릴스 자막편집기/게시물편집기/카테고리A릴스) 구조에서 게시물편집기 탭 위주로 계속 개선.

### 3-1. 마무리 카드 버그
- 카드뉴스 마지막 장이 빈 카드로 나오는 문제. 원인: Claude가 slides 타입을 cover/content 외에 summary·outro·closing 등 제멋대로 지정 → 에디터가 모르는 타입은 렌더 안 됨.
- 해결: ① 프롬프트에 "cover/content 타입만, 마무리는 시스템이 자동 추가" 명시 ② 에디터용 JSON 조립 시 마무리 카드를 항상 자동 추가 ③ 에디터에 타입 정규화 함수(`p_normType`) 추가해 outro/summary 등을 자동으로 closing/content로 변환하는 방어선.

### 3-2. 자막/텍스트 위치 일괄 조정 기능
- 형 요청: "자막 Y좌표가 다 같아야 하는데 하나하나 수동으로 맞추기 번거롭다."
- **↕ Y 일괄 / ↔ W 일괄 / ⬛ 전체 일괄** 버튼 추가. 기준 자막에서 클릭하면 전체에 적용, 이후 개별 조정 가능. 확인창 + 적용 피드백(✔ 적용됨) 포함.

### 3-3. 가운데 정렬 고정 기능
- 자막 박스가 드래그할 때마다 좌우로 흔들리는 문제.
- **⊹ 가운데 고정 ON/OFF** 토글 추가(기본 ON). 켜져 있으면 세로로만 이동, 좌우 핸들 리사이즈도 대칭 확장. JSON 로드 시 자동 중앙 정렬.

### 3-4. 자막 스타일 3종 + 고정 헤드라인 (릴스 자막 편집기)
- 형이 참고한 예시(다이어트 콘텐츠 캡처): 배경 없는 외곽선 스타일 자막 + 영상 전체에 고정된 상단 헤드라인.
- **스타일 3종**: 흰 박스 / 외곽선(배경없음) / 검은 박스. 카드마다 드롭다운 선택 + "스타일 일괄" 버튼.
- **📌 고정 헤드라인** 버튼: 클릭 시 영상 전체 길이로 지속되는 검은박스 자막 자동 추가.
- **중요: 이 기능은 에디터뿐 아니라 렌더러(`generate_daily_reel.py`)도 같이 고쳐야 실제 mp4에 반영됨** — 편집기 CSS만 바꾸면 미리보기만 예뻐지고 최종 영상은 그대로인 함정을 두 번 지적받음(게시물 레이아웃 때도 동일 패턴).

## 4. 게시물 → 릴스 변환기 (generate_post_reel.py + post_reel.yml)

### 4-1. 최초 버전 (줌인 스타일)
- 카드뉴스 PNG를 릴스 mp4로 변환. 슬라이드마다 줌인/줌아웃 켄번즈 효과 + 크로스페이드.

### 4-2. 바이럴 스타일로 전면 개편
- 형 지적: "줌인 별로다. 그냥 일정 시간 보여주고 하드컷으로 넘기는 게 나을 듯."
- 리서치 후 확인: 바이럴 카드뉴스 릴스는 대부분 하드컷. **표지 1.5초 / 본문 1.9초 / 마지막 2.2초**로 재설정. 효과 전부 제거.
- 근거: 릴스 알고리즘은 완주율·재생횟수가 핵심인데, 읽기보다 살짝 빠른 페이싱이 "다시보기"를 유도해 재생수를 늘림.

### 4-3. mp4 생성 불가 문제와 GitHub 경유 우회
- 사지방 크로뮴에 H.264 코덱이 없어서 브라우저 녹화(MediaRecorder)로 mp4를 못 만듦 → webm만 나옴.
- 해결: 에디터에 **🚀 릴스 mp4 (GitHub)** 버튼 추가. GitHub API(Git Data API)로 슬라이드를 `reels_input/`에 자동 업로드 → Actions가 mp4로 렌더 → 완성되면 자동 다운로드. 토큰은 세션 메모리에만 보관(저장 안 함, 공용PC 대응).

## 5. AI 릴스 파이프라인 (힉스필드 MCP) — 스킬 개발과 6라운드 교차검증

### 5-1. 발단
- 형이 업로드한 `vox-motion-graphics-kr.skill`(Vox 스타일 해설영상 자동화 스킬) 분석 요청.
- 평가: 방법론(언어분리 원칙, 스토리엔진, TTS 실측)은 훌륭하나 룩(밝은 콜라주)과 소재(경제해설)가 bodetail과 안 맞음, 비용도 안 맞음(클립당 다수 크레딧, 매일은 무리).
- "발전시켜서 알려달라"는 요청에 **bodetail 전용 스킬로 전면 재설계**하기로 함.

### 5-2. bodetail-reel-kr.skill 1차 제작
- 언어분리원칙 유지(생성모델=영어, 나레이션/자막=한국어, 클립 내 한글절대금지 — 모델이 한글 자소를 뭉갬).
- 룩을 잉크블랙·크림·골드 시네마틱 다크로 전면 교체. NEGATIVE에 밝은색·화이트배경·파스텔 명시적 차단.
- 스토리엔진(관통오브젝트, 질문훅→마지막답, 페이크원테이크, N초마다 임팩트) 그대로 채용.
- **첫 검증에서 자체 발견한 오류**: 존재하지 않는 모델(`gemini_omni`, `nano_banana_pro`) 사용, 조립 도구(`explainer_video`) 실재하지 않음, 캐릭터 고정 방식 오류(Soul 대신 Elements가 맞음 — Soul은 실존인물 사진 학습용이라 일러스트 캐릭터에 부적합).
- 실제 힉스필드 도구 스키마 확인 후 정확한 모델 ID로 교체(`nano_banana_2`, `kling3_0_turbo`, `seedance_2_0`, `seed_audio` 등), Elements 방식(`show_reference_elements`, `<<<element_id>>>` 프롬프트 삽입 문법)으로 수정.

### 5-3. 조립 파이프라인 구축 (assemble_ai_reel.py)
- 스킬 Phase 6("로컬 조립")이 사지방 환경(ffmpeg 없음)에서 실행 불가능하다는 걸 자체 발견 → GitHub Actions 기반 조립기로 전환.
- `videos/ai_reel/`에 `clip_01.mp4`, `voice_01.mp3` 형식으로 올리면 자동 조립. BGM 믹싱, 1080×1920 정규화.

### 5-4. 제미나이 교차검증 6라운드 — 각 라운드 판정과 반영
형이 이 대화의 산출물(스킬+코드)을 제미나이에게 보여주고 받은 피드백을 다시 가져와 검증·반영하는 과정을 6차례 반복. Claude는 매번 "실제로 테스트해서" 판정(맞음/틀림/절충)하고 코드 수정.

**1라운드:**
- ✅ 자막 수동화 병목 → `script.txt` 추가 시 자동 번인 구현
- ✅(절반) 정지 프레임 → setpts 감속(최대 1.25배) 도입, 핑퐁 루프는 방향성 있는 클립에서 어색해서 미채택
- ✅ 파일번호 불일치 → 검증 로직 추가
- ❌(부분) Git 용량 폭발 → `.gitignore`로 videos/ 자체를 빼는 제안은 트리거 구조를 깨서 기각, 대신 아카이브 기본 해제 + Actions 아티팩트 업로드 병행

**2라운드:**
- ✅ 여전히 Git 용량 문제 → `git add reels/` 완전 제거, **결과물은 아티팩트 전용 수령**으로 전환(입력파일만 커밋)
- ✅ 통자막 호흡 문제 → 대본을 2~3구절로 분할, 글자수 비례 타이밍 배분(`phrase_events`)
- ✅(절충) 감속 vs 핑퐁 → 소폭차이는 감속만, 큰 차이는 감속+핑퐁 하이브리드로. 감속상한 1.25→1.15로 하향

**3라운드:**
- ✅ 동시실행 Git충돌 → `concurrency` 그룹 추가(cancel-in-progress)
- ✅ 구절분할의 플리커 현상(0.1초짜리 자막) → 최소노출시간(MIN_SEG=0.7초) 보장, 미달시 이웃 구절과 자동 병합
- ✅(방향전환) 핑퐁의 물리법칙 붕괴(커피 역류 등 글리치) → ffmpeg로 봉합 대신 **근본해결**: 클립을 블록보다 길게(10초) 뽑아서 잘라 쓰는 방식으로 스킬 자체를 수정. 여기서 **자체 발견한 버그**: 스킬은 "잘라쓰기"로 바꿨는데 코드는 여전히 긴 쪽(`max`)에 맞추고 있어서 8초클립+4.7초보이스가 8초블록이 되는 오류 → `min`(나레이션 길이 기준)으로 수정.

**4라운드:**
- ✅ 경고(WARN) 증발 문제 → `die()` 공통 예외처리 함수로 종료 전 누적 경고 항상 출력
- ✅ 오디오 클리핑 → `alimiter` 리미터 추가, 실측으로 클리핑 없음 확인
- ✅ 가짜성공(3회 push 재시도 실패해도 exit 0) → 명시적 `exit 1` + `::error::` 어노테이션

**5라운드 (엔터프라이즈 표준 지적):**
- ✅ 파일명 검증 허술 → 정규식(`clip_01.mp4` 엄격 매칭)으로 교체, 0바이트 파일 차단, ffprobe 타임아웃
- ✅ EBU R128 라우드니스 미준수 → 2패스 loudnorm으로 -14 LUFS 정규화 구현, 실측 정확히 -14.0 확인
- ✅ 세대손실(재인코딩 누적) → 중간물 crf14, 최종만 crf19 1회 인코딩
- ✅ 순차처리 비효율 → ThreadPoolExecutor 병렬 렌더링
- ❌ S3/R2 오브젝트스토리지 전환 → 사지방 브라우저 환경에 과함, 기각. 대신 러너버전 고정(`ubuntu-24.04`)으로 결정성 확보
- ❌ Docker 컨테이너화 → 과함, 기각

**6라운드:**
- ❌ **기각(사실관계 오류 발견)**: `git-auto-commit-action`이 "알아서 원격 병합해준다"는 주장 → 웹서치로 확인한 결과, 해당 액션 공식 문서는 명시적으로 rebase/merge 미지원이라고 밝히고 있고, 메인테이너 본인이 관련 기능요청을 거절한 이력 확인. 오히려 이슈트래커에 정확히 같은 실패사례(동시 push 충돌) 다수 보고됨. **채택 안 함.**
- ✅ 문제의식(쉘 스크립트 리베이스 데드락 우려)은 타당 → 더 나은 방식으로 해결: 우리 작업은 "파일 삭제"뿐이라 리베이스 자체가 불필요. 매 시도마다 원격 최신으로 `reset --hard` 후 재적용하는 멱등 방식으로 전환.
- **이 라운드를 마지막으로 검토 중단 결정.** 사실관계 오류가 나온 것 자체가 "더 파고들 실제 결함이 바닥났다"는 신호로 판단, 이후는 실행에서 배우는 게 낫다고 합의.

### 5-5. 운영 매뉴얼 작성
- `AI릴스-운영매뉴얼.md`: A(최초설치)/B(캐릭터생성)/C(클립라이브러리18개)/D(매일루틴) 4단계로 정리.
- 핵심 설계: **클립 재사용이 비용의 핵심.** 캐릭터 Element 1회 생성 후 영구 재사용, 클립 라이브러리(오프닝3·전환3·무드배경6·캐릭터4·아웃트로2=18개) 1회 구축 후 매일은 보이스만 새로 생성.
- 하루 소요시간 약 15분으로 설계(파일명 규칙 맞추기가 유일한 수작업 구간).
- **형의 "Vox 수준 퀄리티가 나오느냐"는 질문에 대한 정직한 답**: 일관성(브랜드톤 고정)은 강하게 보장되지만, Vox의 깊이는 몇 주짜리 저널리즘 취재에서 나오는 거라 종목 자체가 다름. "매번 준수한 물건"은 보장되지만 "매번 걸작"은 아님. 그리고 실제 퀄리티의 8할은 스킬이 아니라 클립 라이브러리 실물 품질에 달려있다고 명시.

### 5-6. 힉스필드 크레딧 확인 이력
- 최초 확인 시 잔액 0, 무료플랜. 트라이얼 안내(3일무료, 자동갱신 주의) 제공.

## 6. Anthropic API 크레딧 소진 사고 (별개 이슈)

- 게시물+릴스 자동화가 갑자기 실패. 로그: `Your credit balance is too low`.
- 형이 "무료인 줄 알았다"고 당황 → 설명: claude.ai Pro 구독과 API 크레딧(console.anthropic.com)은 완전히 별개 결제 시스템. API는 선불 크레딧 방식으로, 매일 자동화 호출이 누적돼서 소진된 것.
- 대시보드 확인: 크레딧 -$0.64, 이번달 지출 $3.79/$1000한도(이 한도는 안전장치 카운터일 뿐 크레딧 재충전 아님).
- 최근 가격인상 의혹은 확인 결과 해당없음(코드가 쓰는 claude-sonnet-4-6은 가격 변동 없었음, 순수 누적사용).
- **형 결정: 매일 자동 스케줄을 다 끄고 게시물 생성 하나만 남기기로 함.** (Actions 화면에 리버니네일/카테고리A릴스/DailyReelGenerator/주간학습 등 다수가 매일 실패 반복 중이던 걸 발견 후)
- **끄는 방법 안내**: 각 yml의 `schedule:` 블록만 삭제, `workflow_dispatch:`는 유지 → 수동실행 버튼만 남김.
- 이후 충전 완료.

## 7. 환경 전환 (사지방 → 집 PC, Claude Code 복귀)

- 형이 원래 Claude Code + 옵시디언 볼트(`bodetail-vault`, `.obsidian`, `content/`, `market/`, `product/` 등 온톨로지 구조)로 작업하던 사람이었음. 사지방 기간엔 이게 끊겨 있었음.
- 복귀 후 "GitHub에 코드파일만 반영되고, 그 사이 판단근거·시행착오는 대화에만 남아있다"는 걸 형이 정확히 지적 — 단순히 코드 파일만 보고 지식화하면 "왜 이렇게 만들었는지"가 통째로 빠진다는 것.
- **해결 방향**: 이 대화 전체를 텍스트로 추출해서 볼트 `raw/`에 넣고, Claude Code가 이 파일을 근거로 `marketing_auto/`(무엇을 만들었나)와 `decisions/`(왜 이렇게 결정했나, 시행착오, 미해결이슈)에 나눠 지식화하기로 함.
- **환경 전환에 따른 구조 변화 논의 중**: 사지방 제약(GitHub Actions 경유, 파일명 수동 매칭 등)이 사라지므로, AI 릴스 파이프라인을 Claude Code 로컬 실행으로 전환하는 게 유리하다는 데 합의. `assemble_ai_reel.py`는 로컬에서도 그대로 재사용 가능(오히려 Actions 대기시간 없이 더 빠름). 단, **게시물 자동화(매일 아침)는 컴퓨터가 꺼져있어도 돌아야 하므로 GitHub Actions + Anthropic API 키 구조를 그대로 유지**하기로 함. API 키가 완전히 필요없어지는 게 아니라 릴스 쪽 부담만 줄어드는 것.

## 10. 핵심 교훈 (반복 패턴으로 나타난 것들)

3. **외부 검토(제미나이)를 받아오는 패턴이 유효했음** — 5라운드는 실제 결함을 찾아 코드 개선에 기여, 6라운드째에 사실관계 오류가 나온 걸 신호로 검토를 스스로 종료. 맹신하지 않고 매번 실측/웹서치로 검증 후 반영.

## 12. 타깃(20~34 한국 남성) 심리 분석 — 콘텐츠 기획 기준

형의 "이 그룹에게 바이럴하려면 뭘 갖춰야 하나" 질문에 대한 분석. 콘텐츠 방향의 기준으로 계속 참조할 것.

**① 관리한다는 걸 들키기 싫어한다.** 외모에 신경 쓰면서도 애쓴 티가 나는 걸 창피해함. "이렇게 꾸며라"는 반응 없고 **"티 안 나게", "남들 모르게", "노력 안 한 것처럼"**은 저장됨. 세르칸의 "귀티나는 디테일"이 통하는 지점. → 우리 DAY1 주제 "'꾸민 티' 없이 좋아 보이는 원칙"도 같은 축.

**② 조용히 반응한다.** 그루밍 콘텐츠에 좋아요를 잘 안 누름. 대신 저장하고 DM으로 친구에게 보냄. → **좋아요 수로 성과를 판단하면 오판. 저장률·공유수가 진짜 지표.**

**③ 서열·등급 프레임에 반응한다.** 티어리스트, "상위 20%가 하는 것", "이거 모르면 아직". → A4(랭킹) 원형이 이 층을 때림.

**④ 제3자 검증을 원한다.** "여자들이 실제로 보는 곳", "소개팅에서 감점되는 3가지" — 타인의 시선을 근거로 제시할 때 설득력 급상승.

**⑤ 숫자를 신뢰한다.** 수치·조건분기가 특히 잘 먹힘(이미 구체성 테스트로 반영됨).

**바이럴 장치별 정리:**
- **저장 트리거**: 순서·절차, 가격 비교표, 나중에 살 것 목록 → 마지막 장에 "저장해두고 살 때 꺼내보세요"
- **공유 트리거**(팔로워 증가의 실질 엔진): "이거 못 지키는 친구 있죠", "이런 사람 주변에 한 명씩 있음" — **남자는 자기가 저장하는 것보다 친구 놀리려고 보내는 걸 더 많이 함**
- **댓글 트리거**: 논쟁 지점 하나를 일부러 남김("이건 호불호 갈릴 텐데", "다들 어디서 사세요?")
- **첫 3초**: 이득보다 손실 회피가 강함. "이렇게 하면 좋아진다"보다 "이거 하나가 인상을 깎는다"가 3초 유지율 높음

**준영만의 무기 (전략적으로 중요)**: 초기 1,000~10,000명은 **군인·대학생층**에서 나옴(돈은 없지만 정보 갈증 크고 참여도 압도적). 준영은 지금 그 안에 있어서 PX에서 뭘 살 수 있는지, 훈련 끝나고 뭐가 급한지를 경험으로 아는 사람이 이 니치에 거의 없음. **AI가 못 만드는 콘텐츠.** "군인 그루밍"으로 계정 정체성을 반쯤 잡고 시작해서 전역 후 일반 남성으로 확장하는 경로 제안됨.

## 13. 시스템 성숙도에 대한 냉정한 평가 (합의된 인식)

형의 "이 정도면 바이럴되어 팔로워 많이 늘 수준이냐" 질문에 대한 답변. **낙관하지 않기로 한 지점들:**

- 지금까지 한 작업은 전부 **품질의 하한선**을 올리는 일. 그런데 인스타 성장은 평균이 아니라 **아웃라이어**가 만듦. 분산을 줄이는 설계는 역설적으로 터질 확률도 깎음.
- **병목 4개(영향력 순)**: ①게시물→릴스 슬라이드쇼는 도달 보너스지 성장 엔진이 아님(움직임·목소리·얼굴 없음) ②사진이 서양인 스톡이라 이입 안 되고 "AI로 찍어낸 계정" 냄새 ③얼굴·목소리 없는 계정의 구조적 한계 ④전부 에버그린 주제라 "지금 올려야 할 이유"가 없음(시의성 축이 비어 있음)
- **현실적 예상**: 성실히 올리면 3~4개월에 1,000~2,500명. Stage 1 목표는 달성하나 Stage 2(1만)는 릴스가 최소 한 번 터져야 나오는 숫자.
- **우선순위 제안**: 1순위 네이티브 릴스 전환(+TTS), 2순위 Soul/Elements 캐릭터로 스톡 문제 해결, 3순위 시의성 트랙 신설, 4순위 배포 작업(벤치마크 계정 댓글 — 유일하게 자동화 불가, 팔로워 0~1000 구간에서 콘텐츠만큼 효과 큼)
- **합의된 결론**: "자동화가 만드는 건 공급이고, 바이럴은 선택에서 나온다. 시스템 90% + 판단 10%인데 그 10%가 성패를 가른다."

## 14. 기타 처리된 사소한 이슈들

- **GitHub 25MB 업로드 제한**: 카카오톡 영상(26.5MB)을 22.2MB로 압축(HEVC→H.264 변환, 해상도·길이 유지)해 해결. 향후 큰 파일은 Git Data API 경유 업로드 방식 검토.

- **아티팩트 파일 다운로드 방법**: GitHub 코드 에디터(Edit 모드)에는 다운로드 버튼이 없음 → 파일 보기 화면에서 우측 상단 다운로드 아이콘 사용.
- **화질 유지 폰 전송**: 카톡은 강제 압축되므로 부적합. 구글 드라이브 또는 **폰 브라우저로 GitHub Actions 아티팩트 직접 다운로드**가 최선(PC 경유 자체가 불필요).
- **인스타 웹 업로드는 음악 추가 불가** — 트렌딩 오디오를 쓰려면 반드시 모바일 앱에서 업로드해야 함. 웹에서 올리려면 BGM이 내장된 `reel_final.mp4`를 써야 함.
- **캐러셀 이미지 잘림**: 비율 불일치가 원인. 인스타 업로드 시 좌하단 확대/축소 아이콘을 눌러 4:5 전체 비율로 맞춰야 함.
