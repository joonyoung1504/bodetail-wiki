> Ollama/Antigravity 하이브리드 라우팅)과는 다르게, 실제로는 GitHub Actions + Python 스크립트 + 힉스필드

## 실제 저장소 구조 (bodetail-wiki, GitHub Private)

```
.github/workflows/
├── daily_post.yml          (유지 — 매일 자동)
├── daily_reel.yml          (스케줄 끔)
├── nail_post.yml           (스케줄 끔, 별도 브랜드 — 리버니)
├── category_a.yml          (스케줄 끔)
├── weekly_learn.yml        (스케줄 끔)
├── post_reel.yml           (게시물→릴스 변환, 트리거식)
└── ai_reel.yml              (AI릴스 조립, 트리거식 — 로컬전환 검토중)
generate_daily_post.py       게시물 자동생성
generate_daily_reel.py       카테고리A/B 릴스 생성
generate_post_reel.py        게시물→릴스 하드컷 변환기
assemble_ai_reel.py          AI릴스 조립기
fetch_ig_insights.py         인스타 인사이트 수집
learn_from_results.py        주간 학습기
content/{topics_30.json, topic_formula.md, topic_domains.md, learnings.md}
posts/topic_state.json       순환 상태
tools/bodetail_editor.html   게시물/릴스자막 편집기
assets_audio/bgm/            BGM 저장소
```

## 게시물 → 릴스 변환기 (generate_post_reel.py)

- **1차(줌인 스타일)**: 슬라이드마다 줌인/줌아웃 켄번즈 + 크로스페이드.
- **2차(바이럴 스타일 전면 개편)**: "줌인 별로다, 하드컷이 낫다"는 지적 → 리서치 결과 바이럴 카드뉴스 릴스는 대부분 하드컷으로 확인. **표지 1.5초 / 본문 1.9초 / 마지막 2.2초**로 재설정, 효과 전부 제거. 근거: 릴스 알고리즘은 완주율·재생횟수가 핵심인데 읽기보다 살짝 빠른 페이싱이 "다시보기"를 유도해 재생수를 늘림.
- **mp4 생성 불가 문제**: 사지방 크로뮴에 H.264 코덱이 없어 브라우저 녹화(MediaRecorder)로 webm만 나옴 → 에디터에 **🚀 릴스 mp4 (GitHub)** 버튼 추가. GitHub API(Git Data API)로 슬라이드를 `reels_input/`에 업로드 → Actions가 mp4로 렌더 → 자동 다운로드. 토큰은 세션 메모리에만 보관(공용PC 대응, 저장 안 함).

## 실행 분업 원칙 (로컬 vs GitHub Actions)

| 작업 | 실행 위치 | 이유 |
|---|---|---|
| 게시물 자동화(매일 아침) | **GitHub Actions 유지** | PC 꺼져있어도 아침에 나와야 함 |
| AI 릴스 파이프라인 | **로컬(Claude Code) 전환 유리** | Actions 대기시간 없이 더 빠름, assemble_ai_reel.py는 로컬 재사용 가능 |

환경 전환(사지방→집PC) 논의에서 합의된 원칙: **사지방 제약(Actions 경유, 파일명 수동매칭)이 사라지므로 AI릴스는 로컬로 옮기는 게 유리하지만, 게시물 자동화는 컴퓨터가 꺼져 있어도 돌아야 하므로 GitHub Actions + API 키 구조를 그대로 유지**한다. API 키가 필요없어지는 게 아니라 릴스 쪽 부담만 줄어드는 것.

## Anthropic API 크레딧 소진 사고

- 게시물+릴스 자동화가 갑자기 실패. 로그: `Your credit balance is too low`.
- **claude.ai Pro 구독과 API 크레딧(console.anthropic.com)은 완전히 별개 결제 시스템** — API는 선불 크레딧 방식으로, 매일 자동화 호출이 누적돼 소진됨.
- 확인 결과: 최근 가격인상 의혹은 해당없음(사용 모델 가격 변동 없었음, 순수 누적사용).
- **대응 결정**: 매일 자동 스케줄을 다 끄고 게시물 생성 하나만 남김. Actions 화면에 여러 워크플로(리버니네일/카테고리A릴스/DailyReelGenerator/주간학습)가 매일 실패 반복 중이던 것을 발견 후 결정.
- **끄는 방법**: 각 `.yml`의 `schedule:` 블록만 삭제, `workflow_dispatch:`는 유지해 수동실행 버튼만 남김. → 로컬로 옮긴 워크플로도 이 원칙 적용.

## 환경 전환 (사지방 → 집 PC, Claude Code 복귀)

사지방 기간엔 GitHub 웹 UI로만 코드를 커밋했고 Claude Code·옵시디언 볼트 연동이 끊겨 있었음. 복귀 후 핵심 발견: **"GitHub엔 코드 파일만 반영되고, 판단근거·시행착오는 대화에만 남아있다"** — 코드만 보고 지식화하면 "왜 이렇게 만들었는지"가 통째로 빠짐. 해결: 대화 전체를 텍스트로 추출해 `raw/`에 저장 → Claude Code가 이를 근거로 `marketing_auto/`(무엇을 만들었나)와 `decisions/`(왜·시행착오·미해결)로 나눠 지식화(이 작업 자체가 그 결과물).

## 기타 처리된 소소한 이슈

- **GitHub 25MB 업로드 제한**: 카카오톡 영상(26.5MB)을 22.2MB로 압축(HEVC→H.264, 해상도·길이 유지)해 해결.
- **subtitles.json**: Actions가 생성하는 자막 설계도(텍스트·타이밍·박스좌표). 영상만으로는 편집 불가, 반드시 mp4와 짝으로 편집기에 로드해야 함.
- **인스타 웹 업로드는 음악 추가 불가** — 트렌딩 오디오를 쓰려면 모바일 앱 업로드 필수. 웹 업로드 시엔 BGM 내장된 `reel_final.mp4` 사용.
- **캐러셀 이미지 잘림**: 비율 불일치가 원인 — 업로드 시 4:5 전체 비율로 맞춰야 함.
