# AI 릴스 파이프라인 (힉스필드 MCP)

> 출처: [[raw/2026-07~08_사지방기간_전체기록]] §5. 사지방 기간 동안 힉스필드(Higgsfield) MCP를 이용해
> bodetail 전용 AI 릴스 생성 스킬을 처음부터 만들고, 제미나이 교차검증을 6라운드 거친 기록.

## 발단

형이 업로드한 `vox-motion-graphics-kr.skill`(경제 해설 영상 자동화 스킬)을 분석한 결과: 방법론(언어분리 원칙·스토리엔진·TTS 실측)은 훌륭하나 룩(밝은 콜라주)과 소재(경제해설)가 bodetail과 안 맞고 비용도 안 맞음(클립당 다수 크레딧, 매일은 무리) → bodetail 전용으로 전면 재설계하기로 결정.

## bodetail-reel-kr.skill 설계

- **언어분리 원칙 유지**: 생성모델=영어, 나레이션/자막=한국어, 클립 내 한글 절대 금지(모델이 한글 자소를 뭉갬)
- **룩 전환**: 잉크블랙·크림·골드 시네마틱 다크. NEGATIVE 프롬프트에 밝은색·화이트배경·파스텔 명시적 차단
- **스토리엔진 채용**: 관통오브젝트, 질문훅→마지막답, 페이크원테이크, N초마다 임팩트
- **자체 발견한 오류(1차 검증)**: 존재하지 않는 모델(`gemini_omni`, `nano_banana_pro`) 사용, 조립 도구(`explainer_video`) 실재하지 않음, 캐릭터 고정 방식 오류(실존인물 학습용 Soul 대신 일러스트엔 [[concepts/힉스필드Elements]]가 맞음) → 실제 도구 스키마 확인 후 정확한 모델 ID(`nano_banana_2`, `kling3_0_turbo`, `seedance_2_0`, `seed_audio`)와 Elements 방식(`<<<element_id>>>` 프롬프트 삽입 문법)으로 교체.

## 조립 파이프라인 (assemble_ai_reel.py)

스킬 Phase 6("로컬 조립")이 사지방 환경(ffmpeg 없음)에서 실행 불가능함을 자체 발견 → GitHub Actions 기반 조립기로 전환. `videos/ai_reel/`에 `clip_01.mp4`, `voice_01.mp3` 형식으로 업로드하면 자동 조립(BGM 믹싱, 1080×1920 정규화).

## 제미나이 교차검증 6라운드

형이 스킬+코드를 제미나이에게 보여주고 받은 피드백을 다시 가져오면 Claude가 매번 **실제로 테스트해서** 판정(채택/기각/절충)하고 코드 수정하는 과정을 6차례 반복.

| 라운드 | 핵심 채택 사항 | 핵심 기각 사항 |
|---|---|---|
| 1 | script.txt 자동 번인, 정지프레임→감속(최대1.25배) | Git 용량 대책으로 videos/ 전체 제외(트리거 구조 파괴) |
| 2 | Git 용량 → 결과물 아티팩트 전용 수령 전환, 통자막 분할+글자수 비례 타이밍 | 감속상한 1.25→1.15로만 절충 |
| 3 | 동시실행 Git충돌 → concurrency 그룹, 플리커 방지 최소노출 0.7초 | 핑퐁의 물리법칙 붕괴 → ffmpeg 봉합 대신 **클립을 블록보다 길게 뽑는 근본 해결**로 전환 |
| 4 | 경고 증발 → die() 공통 예외처리, 오디오 클리핑 → alimiter, 가짜성공 → exit 1 명시 | — |
| 5 | 파일명 정규식 검증, EBU R128(-14 LUFS) 정규화, 세대손실 방지(중간crf14/최종crf19), 병렬렌더링 | S3/R2 전환(과함), Docker화(과함) — 대신 러너버전 고정으로 결정성 확보 |
| 6 | 리베이스 데드락 우려는 타당 → "파일 삭제뿐이라 리베이스 불필요"로 판단, `reset --hard` 후 재적용하는 멱등 방식 채택 | **`git-auto-commit-action`이 "알아서 원격 병합해준다"는 주장 — 웹서치로 확인 결과 사실관계 오류(공식문서가 명시적으로 미지원, 메인테이너가 관련 기능요청 거절 이력)로 판명, 기각** |

**6라운드에서 검토 중단 결정**: 사실관계 오류가 나온 것 자체를 "더 파고들 실제 결함이 바닥났다"는 신호로 판단, 이후는 실행에서 배우는 게 낫다고 합의.

## 운영 매뉴얼

`AI릴스-운영매뉴얼.md`: A(최초설치)/B(캐릭터생성)/C(클립라이브러리18개)/D(매일루틴) 4단계.

- **클립 재사용이 비용의 핵심**: 캐릭터 [[concepts/힉스필드Elements]] 1회 생성 후 영구 재사용, 클립 라이브러리(오프닝3·전환3·무드배경6·캐릭터4·아웃트로2=18개) 1회 구축 후 매일은 보이스만 새로 생성.
- 하루 소요시간 약 15분 설계(파일명 규칙 맞추기가 유일한 수작업 구간).
- **정직한 품질 평가**: 일관성(브랜드톤 고정)은 강하게 보장되지만, Vox 수준의 깊이는 몇 주짜리 저널리즘 취재에서 나오는 거라 종목 자체가 다름 — "매번 준수한 물건"은 보장, "매번 걸작"은 아님. 실제 퀄리티의 8할은 스킬이 아니라 클립 라이브러리 실물 품질에 달려있음.

## 크레딧 상태

최초 확인 시 잔액 0, 무료플랜. balance/generate_video 등 실제 도구 호출은 여러 차례 "No approval received"로 실패 — **형의 승인 없이는 실행 안 됨을 재확인**.

## 미착수 항목

- B단계(캐릭터 생성): 크레딧 0으로 보류 중, 충전 예정
- C단계(클립 라이브러리 18개): 미착수
- Claude Code 로컬 실행으로 전환: 세부 설계는 논의만 됨 — [[marketing_auto/MA_07_시스템아키텍처-실행분업]] 참조
